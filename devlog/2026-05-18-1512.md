# 0518-1512 — plane snap 한계 확인 → 논문 아이디어 변형 shared base/group module 구현 → surface outlier 진단

이번 세션은 이전/다른 세션에서 진행된 **plane snap 기반 OBB 정렬 시도**의 결과를 인계받은 상태에서 시작했다. 핵심 문제는 여전히 동일했다:

> 객체 표면으로부터 생성된 hidden/base geometry가 인접 part 내부로 겹친다. 원래 OBB로 생성하는데 part별 OBB/hidden box 각도가 조금씩 휘고, cabinet 내부를 각 part가 독립적으로 차지해서 옆 part와 겹친다.

세션 최종 상태:
- `shared_bases` 기반의 **group-level static hidden/base shell** 생성 로직을 새로 만들었다.
- 서로 다른 크기의 표면이 한 그룹으로 묶여도, **layout module** 단위로 box를 잘라 생성하도록 바꿨다.
- divider도 생성한다.
- shared box 축이 module마다 다르게 도는 문제를 수정해서, 지금은 **group parent canonical frame** 하나를 공유한다.
- 현재 box front rect는 사용자의 지시에 따라 **raw min/max** 기준이다. percentile/robust rect 보정은 되돌렸다.
- 다음 병목은 `mesh_030`, `mesh_218` 같은 일부 `part.ply/mask_mesh_refined.ply` 표면 품질 문제다. 다음 세션은 `scene2part/s2p_6.py`의 surface refinement를 고치는 게 맞다.

## 0. 시작 시점 인계 내용

다른 세션에서 이미 아래 흐름이 진행된 상태였다.

### 0.1 Stage 1 / Stage 2 plane snap 시도

목표:
- `part.ply` 표면이 약간 기울거나 boundary outlier 때문에 OBB가 휘는 문제를 줄인다.
- OBB/cuboid/base axis가 part 표면과 더 평행하게 되도록 만든다.

진행:
- Stage 1: `scene2part/s2p_5.py`에서 face filtering.
  - `mesh_518`: 약 7.3% face 제거.
  - `mesh_519`: 약 15.6% face 제거.
  - 방향은 좋아 보였다.
- Stage 2: `part2interactive/visualization.py` 쪽에서 `_snap_mask_to_plane`를 통해 plane 기반 snap을 시도.

문제:
- vertex를 plane 위로 직접 projection하자, OBB의 thin axis 길이가 0에 가까워졌다.
- downstream에서 thickness/coverage ratio가 깨지면서 part2interactive가 전부 reject:
  - `"Mask coverage ratio is too low: 0.0"`
  - part 0개 생성.
- 그래서 projection은 빼고 outlier filtering만 유지하는 방향으로 수정.

실제 효과:
- OBB tilt 평균은 줄었다.
  - before 약 `1.70 deg`
  - after 약 `0.88 deg`
  - 대략 50% 감소.
- 하지만 hidden geometry/base overlap은 충분히 해결되지 않았다.
- 특히 `mesh_518`, `mesh_519`처럼 같은 cabinet 내부를 공유하는 part는 cuboid depth가 그대로라 시각적으로 거의 안 바뀌었다.

### 0.2 중간 측정 오류

인계 로그에 `cuboid_world AABB overlap total 0.156 -> 0.000`처럼 보이는 결과가 있었는데, 이는 잘못된 측정이었다.

원인:
- 당시 worktree의 `part2interactive/inference.py`에는 `cuboid_world.npy` 저장 라인이 빠진 버전이 섞여 있었다.
- 진단 스크립트가 `cuboid_world.npy`를 못 읽고 0으로 측정했다.
- 실제 inference 내부에서는 cuboid/base가 만들어졌고, `base.obj`도 존재했지만 `.npy` 저장이 빠져서 metric만 fake가 되었다.

정직한 결론:
- plane snap/outlier filter는 OBB axis 정렬에는 부분적으로 효과가 있다.
- 그러나 hidden geometry의 핵심 원인인 **per-part cuboid depth가 cabinet 내부를 독립 점유하는 구조**는 해결하지 못했다.

## 1. 문제 재정의

이전 접근은 "각 part의 OBB/cuboid를 더 정확하게 만들자"에 가까웠다.

이번 세션에서 문제를 다시 정의했다:

1. OBB axis가 조금 휘는 문제도 있지만, 그것만으로는 hidden overlap이 해결되지 않는다.
2. 진짜 구조적 문제는 **여러 문/서랍이 하나의 cabinet 내부를 공유하는데, REACT3D는 각 part마다 독립 hidden cuboid/base를 만든다**는 점이다.
3. 따라서 shared interior/base를 하나로 만들거나, 적어도 같은 cabinet group 안에서 module 단위로 잘라야 한다.

즉:

```text
기존:
  mesh_518 base.obj = 자기 문 뒤 cabinet 전체 깊이
  mesh_519 base.obj = 자기 문 뒤 cabinet 전체 깊이
  => 두 base가 같은 내부 공간을 중복 점유

새 방향:
  같은 cabinet plane의 part를 group으로 묶고
  group/module 단위 static shared base shell을 하나만 생성
  grouped part의 old per-part base.obj는 시각화/URDF에서 숨김
```

## 2. 참고한 논문/아이디어와 변형

사용자가 "최신 25/26 논문에서 아이디어를 가져와 우리 걸로 변형하자"라고 해서, 이전 서베이에서 다룬 방향을 이번 구현에 반영했다.

### 2.1 DRAWER 계열 아이디어

참고 정신:
- object/part를 canonical primitive/box로 fit한다.
- 인접 drawer/door 사이 inter-penetration을 피하는 loss/prior가 중요하다.
- 각 part를 독립 cuboid로 두면 shared interior를 표현하기 어렵다.

우리 변형:
- heavy optimization/SGD fitting은 하지 않았다.
- 대신 closed-form post-process로:
  - coplanar/nearby articulated parts를 group.
  - group/module 단위 open shell을 생성.
  - old per-part hidden cuboid를 숨겨 중복 점유를 제거.

### 2.2 MoMa-SG / ArtPro 계열 구조 prior

참고 정신:
- object는 part들의 단순 집합이 아니라 structural grouping/scene graph 관계가 있다.
- part가 같은 parent object 또는 같은 cabinet compartment에 속하는지 보는 게 중요하다.

우리 변형:
- semantic graph를 직접 만들지는 않았다.
- 대신 geometry 기반으로 parent group을 만든다:
  - front normal 유사.
  - 같은 plane 근처.
  - front layout 상 가까움.
  - 또는 기존 `base.obj` AABB overlap 존재.
- 이 connected component를 "shared base group"으로 간주한다.

### 2.3 Manhattan / canonical frame prior

사용자가 지적한 핵심:
- shared box는 보통 직사각형이고, cabinet이면 world-Z vertical 및 parent object frame이 있어야 하는데 왜 module마다 rear/depth vector가 다르냐.

정리:
- 직사각형이라는 말은 box 내부 축끼리 직교한다는 뜻이지, 무조건 world XYZ와 일치한다는 뜻은 아니다.
- 하지만 indoor cabinet/door/drawer의 parent frame은 보통 world-Z vertical을 공유하는 게 강한 prior다.

우리 변형:
- module별 PCA frame을 버렸다.
- group 하나당 parent canonical frame을 하나만 fit한다.
- vertical은 정확히 world Z `[0,0,1]`.
- normal/depth는 group surface normal을 horizontal plane에 project해서 사용.
- horizontal은 `cross(vertical, normal)`.

현재 결과:
- 같은 group 내부 모든 module의 axes가 동일.
- vertical은 world Z와 0도.
- frame dot product도 0.

### 3.1 PartInfo 로딩

각 `mesh_*` 폴더에서 읽는 것:
- `part.ply`: front surface vertices.
- `cuboid_world.npy`: normal/depth/front offset 추정에 사용.
- `base.obj`: 기존 hidden overlap 기반 pair linking에 사용.

주의:
- 현재 `part.ply`는 raw vertices 그대로 사용한다.
- 다음 세션에서 표면 outlier를 제거하면 이 raw vertices 기준 box도 자연스럽게 좋아지는 구조다.

### 3.2 group linking 기준

두 part를 같은 shared group 후보로 연결하는 기준:

```text

plane gap <= 0.08 m
and (
  front layout in-plane gap <= 0.12 m
  or existing base.obj AABB overlap >= 1e-4
)
```

기본 threshold:

```text
--max_normal_deg 8.0
--max_plane_gap 0.08
--max_inplane_gap 0.12
--min_base_overlap 1e-4
--min_group_size 2
```

그 뒤 connected component로 group을 만든다.

### 3.3 layout module split

처음에는 group 전체를 하나의 shared box로 만들었기 때문에 문제가 있었다.

사용자 관찰:
- `mesh_054, mesh_049, mesh_471, mesh_028`은 같은 group이지만 실제 순서는 왼쪽부터 `054, 049, 471, 028`.
- 구조적으로는 `054,049`와 `471,028`이 각각 묶이는 게 자연스럽다.
- 하나의 큰 group box를 만들면 큰 box와 작은 box가 같이 생기거나, 큰 박스 안에 격자처럼 보이는 문제가 생긴다.

해결:
- group은 유지하되, front layout rect의 크기/겹침을 보고 **layout module**로 나눈다.
- module merge 기준:
  - side-by-side 또는 stacked이어야 함.
  - 공유 span IoU >= `0.82`.
  - 공유 span size ratio >= `0.85`.
  - gap <= `0.06 m`.

현재 기본값:

```text
--module_gap 0.06
--module_span_iou 0.82
--module_size_ratio 0.85
```

현재 module 결과:

```text
group_000: 2 layout modules
  module_000: mesh_028, mesh_471
  module_001: mesh_049, mesh_054

group_001: 4 layout modules
  module_000: mesh_030
  module_001: mesh_196
  module_002: mesh_518, mesh_519
  module_003: mesh_558

group_002: 2 layout modules
  module_000: mesh_077
  module_001: mesh_218
```

### 3.4 divider 생성

사용자 요구:
- 같은 module 안에서도 원래 분리된 문/칸이면 사이에 divider가 있어야 한다.
- 예: `054,049`는 크기가 같아서 같은 module로 묶이지만 사이 칸막이가 필요.

구현:
- `divider_lines_for_module()`에서 module 안 panel pair를 비교.
- side-by-side이면 두 rect 사이 중간 `y`에 vertical divider.
- stacked이면 두 rect 사이 중간 `z`에 horizontal divider.
- `build_open_shell_local()`에서 divider를 thin box로 추가.

divider geometry:
- `divider_y`: local y 고정, depth 방향과 vertical 방향으로 span.
- `divider_z`: local z 고정, depth 방향과 horizontal 방향으로 span.

현재 결과:

```text
group_000/module_000 mesh_028,mesh_471 dividers=1
group_000/module_001 mesh_049,mesh_054 dividers=1
group_001/module_002 mesh_518,mesh_519 dividers=1
```

### 3.5 depth 추정

사용자 관찰:
- 어떤 box는 너무 짧아 보인다.
- 어떤 box는 벽을 뚫고 지나가는 것 같다.

현재 구현:
- module front rect footprint 안에 들어오는 `remain_scene.ply` points를 사용.
- group normal 방향 depth `x`를 계산.
- `x > depth_near_ignore`이고 `x < max_depth`인 점 중 `q90 + margin`을 depth로 사용.
- 점이 부족하면 기존 cuboid depth fallback.

기본값:

```text
--min_depth 0.12
--max_depth 0.60
--depth_quantile 90.0
--depth_margin 0.015
--depth_near_ignore 0.02
--depth_min_points 500
```

현재 depth 결과:


## 4. shared box axis 문제와 해결

### 4.1 문제

처음에는 module별 surface PCA로 frame을 잡았다.

사용자 관찰:
- "shared box끼리 축은 직교하지 않아 보이는데? 박스 후면쪽 벡터가 다 달라."
- "보통 shared box 만들면 직사각형 형태인데 왜 다 이상하냐?"

진단:
- 각 module이 서로 다른 PCA frame을 쓰고 있었다.
- 각 module 내부 축은 직교했지만, 같은 cabinet group 내 module끼리 depth/rear vector가 다르게 보였다.
- 이건 "각 box는 rectangular"이라는 조건은 만족하지만, "같은 parent cabinet frame을 공유"한다는 구조 prior는 만족하지 못했다.

### 4.2 해결

`canonical_group_frame(vertices, normal_hint)` 도입.

현재 frame 구성:

```python
normal = pca_surface_normal(group_vertices)
normal = normal - dot(normal, world_z) * world_z
normal = unit(normal)
vertical = world_z
horizontal = unit(cross(vertical, normal))
```

즉:
- group 전체 surface로 normal fit.
- normal의 Z 성분 제거.
- vertical은 world Z로 고정.
- horizontal은 normal/vertical에 직교.

결과:
- 같은 group 안 module은 모두 동일 `normal/horizontal/vertical`.
- box 후면/depth vector도 group 내에서 같음.

검증:

```text
axis_check max_same_group_axis_angle 0.0
axis_check max_vertical_vs_world_z 0.0
axis_check max_frame_dot 0.0
```

## 7. raw min/max 관련 중요한 결정

세션 막판에 `mesh_030` 표면 outlier 때문에 box가 커지는 문제를 보고, 한 번 임시 보정을 넣었다.

임시 보정 내용:
- largest connected component만 layout fitting에 사용.
- rect를 raw min/max 대신 percentile `0.5% ~ 99.5%`로 계산.

효과:
- `mesh_030` width가 `0.729 -> 0.601` 수준으로 줄었다.
- 즉 outlier가 raw min/max를 밀고 있다는 진단에는 도움이 되었다.

하지만 사용자가 정확히 지적:

> 지금 다른 애들은 raw min/max로 잘 나오는데, 이따가 표면 outlier 제거하면 상관없잖아. raw min/max로 해.

그래서 임시 보정은 전부 제거했다.

현재 상태:
- `rect_for_vertices()`는 순수 raw min/max.

```python
def rect_for_vertices(vertices, horizontal, vertical):
    y = vertices @ horizontal
    z = vertices @ vertical
    return np.array([y.min(), y.max(), z.min(), z.max()])
```

중요:
- 다음 세션에서 box가 다시 커 보인다면 그건 의도된 상태다.
- shared base generator에서 보정하지 말고, upstream `part.ply/mask_mesh_refined.ply` 표면 자체를 정리해야 한다.

검증:

```bash
python -m py_compile simulation_ready/generate_shared_base_groups.py
```

## 9. part surface 품질 문제 진단

사용자 질문:

> 218, 030 같은 애들은 왜 표면 mesh가 깔끔하지 않아? 똑같이 masking해서 point cloud 뽑아오는 건데 왜 그래? 비어 있는 부분도 있고 outlier가 많지? 그래서 030은 육안 가로세로보다 큰 box가 생성돼.

### 9.1 파이프라인 확인

### 9.2 `scene2part/s2p_6.py` refinement 문제

현재 `s2p_6.py`의 핵심:

```python
model, inliers_sub = find_largest_plane(candidate_cloud, ...)
inliers = [candidate_idx[i] for i in inliers_sub]

projections = pts.dot(n_normed)
inlier_proj = projections[inliers]
max_inlier_proj = inlier_proj.max()

rest_idx = np.where(projections > max_inlier_proj)[0].tolist()
plane_idx = np.where(projections <= max_inlier_proj)[0].tolist()
```

문제:
- RANSAC plane의 진짜 inlier만 남기는 게 아니다.
- plane 기준 `projection <= max_inlier_proj`에 걸리는 점을 넓게 포함한다.
- 즉 plane 뒤쪽/옆쪽/작은 face island가 남을 수 있다.
- 어떤 part는 mask/view/geometry가 좋아서 문제 없고, 어떤 part는 이 넓은 selection 때문에 표면이 지저분해진다.

## 10. 왜 일부만 이상한가

같은 masking pipeline을 타도 part마다 입력 조건이 다르다.

원인 후보:

1. View angle 차이
   - 어떤 part는 정면 view가 잘 잡혀 front plane이 안정적이다.
   - 어떤 part는 비스듬하거나 occlusion이 커서 mask boundary가 깨진다.

2. Original scene mesh 품질 차이
   - reconstruction 자체에 구멍이 있으면 masking 후 surface도 비어 보인다.
   - 얇은 문/서랍의 side face, crack, handle 주변 face가 섞이면 RANSAC 이후에도 island가 남는다.

3. `s2p_6.py` plane refinement 방식
   - 진짜 inlier만 쓰지 않고 projection threshold로 넓게 자른다.
   - 이 방식은 좋은 part에서는 괜찮지만, depth 방향으로 복잡한 part에서는 plane 뒤/옆 조각이 같이 남는다.

4. `part.ply`가 p2i에서 후처리되지 않음
   - `part.ply`는 `mask_mesh_refined.ply` copy.
   - p2i는 articulation inference와 base generation에 집중하고, surface cleanup은 하지 않는다.

다음 세션은 shared base generator가 아니라 **surface refinement upstream**을 고쳐야 한다.

### 11.1 추천 수정 방향

현재:

```python
plane_idx = projections <= max_inlier_proj
```

추천:

1. RANSAC plane의 signed distance를 계산.

```python
signed = pts.dot(n_normed) + d_normed
```

2. 실제 plane inlier band만 선택.

```python
plane_idx = np.where(np.abs(signed) <= plane_band)[0]
```

초기값 후보:

```text
plane_band = 0.015 ~ 0.025 m
```

3. mesh extraction 후 largest connected component만 keep.

이유:
- `mesh_030`은 56 components라 작은 island가 raw bbox를 밀고 있다.
- largest component area ratio가 98.48%라, 대부분은 살리고 island만 제거 가능성이 높다.

4. 너무 공격적으로 자르면 구멍이 커질 수 있으므로 debug stats 출력.

추천 출력:

```text
mesh_xxx:
  before verts/faces/components/area
  plane inlier verts/faces/components/area
  largest component area ratio
  raw rect before/after
```

5. `s2p_6.py`만 재실행 후 p2i 재실행.

이유:
- p2i는 `mask_mesh_refined.ply`를 입력으로 읽어 `part.ply`로 복사한다.
- 따라서 refined mesh를 바꾸면 p2i부터 다시 돌려야 한다.

## 14. 짧은 결론

이번 세션에서 hidden geometry overlap 문제는 "part별 cuboid를 잘 보정"하는 문제에서 "shared parent structure를 만들어야 하는 문제"로 한 단계 올라갔다.

구현된 shared base 방식은:
- DRAWER/MoMa-SG/ArtPro류의 canonical primitive + structural grouping prior를 REACT3D에 맞게 가벼운 post-process로 변형한 것.
- optimization 대신 geometry heuristic으로 group/module/static shell을 만든다.
- group parent frame을 써서 shared box axes는 안정화됐다.

남은 가장 큰 병목:
- 일부 `part.ply` 표면 자체가 지저분하다.
- `mesh_030`은 outlier island 때문에 raw bbox가 커진다.
- `mesh_218`은 outlier보다 partial/empty surface 문제가 커 보인다.

다음 세션 첫 작업:

```text
scene2part/s2p_6.py에서 mask_mesh_refined.ply를 진짜 plane inlier + largest component 기준으로 정제한다.
그 후 p2i -> shared base 재생성 -> objects_only/debug_axes 시각화로 확인한다.
```
