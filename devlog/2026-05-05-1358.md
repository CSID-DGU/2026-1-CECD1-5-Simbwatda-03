## 0. 시작 시점 상태

이전 세션 분석에서 확인된 내용:
- **물체 겹침** 원인 = `corners_to_mesh()`가 만드는 `base.obj` (OBB shell)
- base.obj는 part를 감싸는 가짜 박스 → 자기 part.dae와 겹치고, 이웃 part의 OBB와도 겹침
- inner_box.obj (translation만 생성) = OBB 기반 5면 박스 → 이웃과 겹침
- 033/034 같이 part mesh 자체가 겹치는 건 scene2part segmentation 문제 (상위 파이프라인)

## 2. Scene-aware parent body extraction

### 동기
URDF에서 base.obj 빼면 part가 떠있는 상태가 됨. 시뮬 돌리려면 fixed parent body가 있어야 함.
- Option A (OBB - part면): 여전히 가짜 geometry. 인접 part와 겹침 가능.
- Option C (remain_scene crop): 실제 스캔된 문틀/캐비닛/벽이 base body로 들어감.

C 채택. 가짜 geometry 안 만들고 실제 스캔 데이터를 그대로 사용.

### 신규 파일
`REACT3D/simulation_ready/extract_base_from_scene.py`

### 동작
각 part 폴더에 대해:
1. `part.ply` AABB 계산
2. AABB를 30%(`margin_ratio=0.3`) 확장
3. `remain_scene.ply`에서 확장 박스 안에 들어가는 vertices/faces crop
4. `base_scene.obj`로 저장

## 4. Motion-aware collision check (검증)

### 신규 파일
`REACT3D/simulation_ready/check_sweep_collision.py`

### 동기
사용자 가설: sweep volume이 base_scene/remain_scene과 실제로 충돌하지는 않을 것 (문은 어차피 열리려고 디자인된 거니까).

### 동작
1. 각 part를 joint range 0~max_range로 10개 위치 샘플링
2. max-open 위치에서 part vertices와 target mesh의 KDTree nearest neighbor 거리 계산
3. 1cm 이내 verts 개수와 min distance 출력

### 결과
| mesh | own base 1cm 이내 | remain 1cm 이내 | 비고 |
|---|---|---|---|
| mesh_000 | 0/3775 | 0/3775 | clean |
| mesh_002 | 36/28930 | **3084/28930** | max-open에서 다른 구조물 닿음 |
| mesh_023 | 12/12746 | 126/12746 | 약간 닿음 |
| mesh_033 | 0/3442 | 0/3442 | clean |
| mesh_034 | 56/3668 | 1087/3668 | 약간 닿음 |
| mesh_1099 | 32/3321 | 193/3321 | 약간 닿음 |
| mesh_197 | 0/3108 | 0/3108 | clean |
| mesh_408 | 12/3727 | 12/3727 | 약간 닿음 |
| mesh_500 (drawer) | 0/9758 | 0/9758 | min dist 1.5m / 0.46m → 완전히 깔끔 |
| mesh_709 | 0/3118 | 0/3118 | clean |
| mesh_951 | 57/2842 | 103/2842 | 약간 닿음 |
| mesh_970 | 10/2496 | 21/2496 | 약간 닿음 |

### 결론
- 가설 검증 ✅ — 대부분 part는 max-open에서 background와 충돌 없음
- 약간 닿는 케이스들은 문이 fully open일 때 인접 벽/문틀에 살짝 닿는 정도 (정상적인 물리)
- mesh_002만 3084 verts 닿음 — fully open에서 옆 구조물에 박히는 듯, 후속 분석 필요

→ **Motion-aware carving (제거/채우기)은 문(rotation)에는 거의 불필요**

## 5. 노벨티 방향 정리 (멘토와 합의)

이전 세션에서 제시한 3가지:

| 방향 | 현재 상태 |
|---|---|
| **Scene-aware parent body extraction** | 1차 프로토타입 완성 (단순 AABB crop). geometric reasoning(평면 분할, parent surface 자동 추정 등)은 미구현 |
| **Motion-aware space carving** | 시작 안 함. 검증 결과 문(rotation)에는 불필요. 서랍(translation) 내부 hidden geometry를 OBB 대신 carving으로 만들면 의미 있음 |
| **Part-background joint optimization** | 시작 안 함. 033/034처럼 segmentation 노이즈가 큰 케이스에서 효과 예상. 후순위 |
