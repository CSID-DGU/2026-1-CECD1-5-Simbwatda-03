## 1. 최신 25/26 탑티어 논문 서베이

### 1.1 DRAWER (CVPR 2025) — 가장 유사 ★
- 페이퍼: arxiv 2504.15278v1, **github.com/xiahongchi/DRAWER** (코드 공개, 156 stars)
- `/tmp/DRAWER`에 clone, 핵심 파일 `sdf/scripts/fit_doors.py`
- **각 part = `[translate, scale, rotation]` parameters → SGD로 optimize**
- Loss 구성 (`fit_doors.py:1170-1179`):
  ```
  loss = 5*loss_mask + 5*loss_depth + 10*loss_glb + 30*loss_chamfer
  loss_glb = ReLU(-sdf_box(other_drawer_pts) + 0.01).mean()
  ```
- **`loss_glb` = inter-penetration penalty**: 다른 drawer 정점이 자기 box 안에 들어오면 페널티 → 인접 part 충돌 직접 방지
- 우리 문제 (인접 캐비닛 part overlap)를 정확히 해결하는 정신

### 1.2 PhysPart (ICRA 2025) — collision loss formula
- `loss = Σ ReLU(-SDF(p) - α)` (margin α 이상 침투 시 페널티)
- 운동 state도 동일 loss로 처리 (움직일 때도 충돌 방지)
- 우리에 그대로 적용 가능한 수식

### 1.3 Deep Polycuboid Fitting (arXiv 2503.14912, POSTECH)
- bottom-up face aggregation, Manhattan alignment built-in
- face label (±x, ±y, ±z) 강제 → axis-aligned
- 인접 part 간 overlap은 직접 다루지 않음 (single object 위주)
- 코드 공개 X

### 1.4 결론
- DRAWER의 inter-penetration penalty + chamfer fitting이 우리 cuboid_world 보정에 직접 도입 가능
- 그러나 SGD optimization 비용이 헤비 → 우선 가벼운 closed-form heuristic 시도 후 부족하면 DRAWER 스타일로

## 4. cuboid_world 생성 로직 재확인

`visualization.py:1401-1527` `complete_point_cloud_true_mesh`:

```
1. mask_points → oriented_bounding_box_numpy(mask_points)  # OBB
2. OBB의 두 긴 edge → v1, v2
3. face_normal = cross(v1, v2)
4. obb_x, obb_y, obb_normal = OBB의 정규 좌표축
5. scene_pcd에 raycast (get_deepest_in_direction) → proj_max
6. cuboid corners = OBB의 xy 범위 × [proj_min(mask), proj_max(raycast)]
```

**비틀어짐 원인:**
- frame은 OBB axes (이론상 정렬) — 하지만 OBB 자체가 mask 노이즈로 ±1~3° tilt
- `proj_min`: mask 노이즈에 의해 표면 뒤 떨어진 inner outlier로 결정 → cuboid 시작이 표면에서 떨어진 곳
- `proj_max`: raycast가 인접 part나 잘못된 surface hit하면 이상한 깊이

**논문은 cuboid 보정 안 함.** Section III-C refinement는 axis만 (OBB edge로). cuboid corner는 mask 노이즈 + scene raycast에 의존.

## 6. 사용자 핵심 아이디어 — "표면을 진짜 plane으로 snap"

### 6.1 통찰
사용자: "원본은 input에 3d mesh도 있고 depth도 있는데, 지금 표면을 segmentation으로 탐지하고 그거를 mask해서 그거 기준으로 예측한 OBB로 base, inner 만든거라 3d mesh 상의 위치가 안된거 아니야? 표면을 원래 위치로 보내면 나머지도 3d mesh 상의 제자리에 만들어지지 않을까?"

### 6.2 명확화: 두 종류의 노이즈
- **노이즈 A (정점 위치)**: 스캐너 정밀도 — mm 단위, 무시 가능
- **노이즈 B (face 포함 여부)**: segmentation noise — boundary face 한두 개가 cabinet 안쪽/hinge crack face를 잘못 포함. 이 face들의 정점은 위치는 정확하지만 **door 표면 평면에서 벗어난 outlier**
- **PCA가 outlier에 끌려서 OBB yaw 비틀어짐** (1000개 inlier + 5개 outlier만 있어도 thin axis가 ~1° 끌림)

### 6.3 해결 = plane fit + snap
```
mask_mesh vertices → RANSAC plane fit → 진짜 표면 plane (outlier robust)
  → vertices를 plane으로 project (snap) 또는 outlier 제거
  → 깨끗한 평면 위 정점 → OBB compute
  → thin axis = plane normal (정확), 다른 두 axis = plane 내 PCA
  → cuboid_world, base, inner_box 모두 정확한 plane 기반
```

### 6.4 인접 part 자동 정렬 (보너스)
같은 cabinet 면의 두 문은 RANSAC plane fit하면 거의 같은 normal → 두 OBB의 thin axis 동일 → 자동 평행. 인접 정렬도 plane snap 만으로 달성.

### 6.5 구현 옵션
| 옵션 | 위치 | 트레이드오프 |
|------|------|--------------|
| **E1** | `inference.py` OBB compute 직전 — mask_mesh vertices에 plane fit + project | p2i만 재실행 (5분), 가벼움 |
| **E2** | `s2p_*` scene2part 단 — mask_mesh 저장 전에 snap | scene2part 재실행, 더 근본적 |
| **E3** | E1 + 인접 part 그룹 detect → shared plane | 가장 정확, 추가 코드 |

사용자: E1 먼저 시도. 부족하면 E3 확장.

## 8. 다음 세션 할 일 — E1 구현 (표면 plane snap)

### 8.1 구체적 step
1. **`inference.py`에서 OBB compute 위치 식별** — `complete_point_cloud_true_mesh` 직전 또는 그 함수 내부 `oriented_bounding_box_numpy(mask_points)` 호출 부분
2. **Plane RANSAC 추가**:
   ```python
   import open3d as o3d
   pcd = o3d.geometry.PointCloud()
   pcd.points = o3d.utility.Vector3dVector(mask_points)
   plane_model, inliers = pcd.segment_plane(
       distance_threshold=0.01,  # 1cm tolerance
       ransac_n=3,
       num_iterations=200
   )
   ```
3. **두 가지 옵션 중 선택:**
   - **Project mode**: 모든 mask_points를 plane으로 project (vertex 위치를 plane 위로 snap)

   - 우선 **Project mode** 시도 — 더 robust
4. **OBB compute on snapped points** — 자동으로 thin axis가 plane normal로 정렬됨
5. **cuboid_world도 깨끗한 OBB 기반 → base.obj 자동 정렬**
6. **p2i 재실행** (`data/example_input_scene/scene_output_ibsp_filtered/` 새로 생성)
7. **시각 확인** (OBB axes 화살표가 표면 모서리와 평행한지)
8. **진단 스크립트 재실행** (`/tmp/diag_overlap.py`로 overlap 측정)

## 9. 학습/메모

- **per-part 독립 OBB fitting의 한계**: 인접 정보 없으면 minimum-volume OBB가 노이즈에 끌려서 yaw 흔들림. PhysPart/DRAWER 같은 inter-part penalty가 정석.
- **"위치 정확"과 "분포 정확"은 다름**: mask_mesh.vertices의 개별 위치는 정확 (scan 그대로)지만 "어떤 face를 mask에 포함시키느냐"가 분포 노이즈 source. PCA는 분포에 끌림.
- **closed-form heuristic이 SGD보다 우선**: plane fit + snap만으로도 OBB yaw noise 대부분 잡힐 것. DRAWER 스타일 optimization은 마지막 카드.
- **vis_interactive와 URDF gen은 별개 path**: URDF 변경이 자동 반영 안 됨. 시각 변경 필요하면 vis_interactive도 같이 손봐야.
- **vis hierarchy 주의**: `/scene/{subdir}/part_frame/X` 는 part 회전과 같이 움직임. base 고정 geometry는 `/scene/{subdir}/X` 위치 (base level).
