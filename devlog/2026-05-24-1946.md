## 3. 왜 "데이터만 바꿨는데 USDNet이 실패하나"에 대한 현재 결론

사용자 질문:

> pretrain한 USDNet도 같은 코드로 데이터만 다르게 학습한 것 아닌가? 그런데 왜 MultiScan으로 학습하니 실패하나?

현재 답:

1. "같은 코드 + 다른 데이터"만의 문제가 아니라, **초기화/checkpoint/curriculum/domain** 문제가 같이 섞여 있다.
2. USDNet의 좋은 checkpoint들은 이미 ScanNet/Mask3D/openable/movable 관련 prior를 가진 상태일 가능성이 높다.
3. MultiScan으로 처음부터 학습하면 openable foreground가 sparse하고, mask/query/articulation head가 동시에 살아나야 해서 optimization이 어렵다.
4. MultiScan에 articulation label이 어떤 품질/분포로 있는지, USDNet이 기대하는 label format과 얼마나 잘 맞는지도 아직 확실하지 않다.
5. `no targets - train` 로그가 계속 보이는 것도 데이터 샘플 중 foreground가 없는 경우가 꽤 있음을 시사한다. 이것이 학습을 느리게 하거나 불안정하게 만들 수 있다.

그래서 이번에는:

```text
from scratch MultiScan
  -> 실패/매우 불안정

Mask3D pretrained init + MultiScan
  -> clean baseline, 현재 GPU0

mov_trainval init + MultiScan
  -> contaminated upper-bound/teacher, 현재 GPU1
```

이렇게 두 갈래로 보는 중이다.

## 5. 모델별 분석

### 5.1 S2O — 가장 목표에 가깝지만 direct replacement는 아님

S2O는 "Static to Openable" task를 다룬다.

목표:
- static container mesh를 articulated openable object로 바꾸기.
- part segmentation
- motion prediction
- interior completion

중요 코드:

```text
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/s2o/pipeline_exp/pipeline_connectivity.py
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/s2o/motion_inference.py
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/s2o/opmotion/engine/motion_predictor/rule_motion_predictor.py
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/s2o/scripts/postprocess/postprocess_fpngroupmot_motion.py
```

핵심 구조:
- input mesh에서 surface point를 200k sample.
- FPS로 20k 정도 downsample.
- point xyz/normal을 normalize.
- FPNGroup/PointGroup/Mask3D 등으로 part segmentation.
- point prediction을 mesh connectivity로 다시 mapping.
- part point cloud AABB/CatBox를 만들고, rule-based motion predictor로 joint type/origin/axis 추론.

S2O README 기준 segmentation 성능 힌트:
- FPNGroup이 PM-Openable에서 가장 추천되는 쪽.
- Mask3D는 S2O task에서는 성능이 높지 않게 보고되어 있음.
- 이는 "USDNet의 mask backbone만으로 openable part surface를 깨끗하게 얻기 어렵다"는 현재 관찰과도 잘 맞는다.

motion predictor 특징:
- semantic class가 base/drawer/door/lid 정도로 가정됨.
- drawer는 prismatic, axis는 front direction, origin은 box center.
- door/lid는 revolute, parent box와 part box 관계 및 handle 위치 heuristic으로 hinge edge 선택.

해석:
- S2O는 openable에 매우 가깝지만, scene-level USDNet 대체라기보다는 **object mesh 중심 pipeline**이다.
- REACT3D/Articulate3D scene point cloud에 바로 꽂기에는 전처리/가정이 다르다.
- 당장 쓸 곳은:
  1. USDNet mask 후처리/refinement 비교군
  2. axis/origin heuristic fallback
  3. pseudo-label/teacher
  4. "clean object mesh가 있을 때 upper-bound" 실험

### 5.2 GeoSAM2 — clean mesh surface label/refinement에 강함

GeoSAM2는 CVPR 2026 쪽으로 확인된 geometry-aware SAM2 mesh segmentation 모델.

중요 코드:

```text
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/GeoSAM2/inference.py
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/GeoSAM2/utils/inference_utils.py
/home/gpuadmin/capstone/USDNet/REACT3D/research_repos/GeoSAM2/sam2/modeling/sam2_base_geosam2.py
```

핵심 구조:
- mesh를 여러 view로 render.
- color, alpha, depth, normal, meta를 사용.
- 2D click/mask를 SAM2 video predictor로 view 간 propagate.
- sampled face points를 각 view에 project해서 2D mask label을 읽고, mesh face label로 lift.
- `complete_labels` 후처리로 작은 component 제거 및 unlabeled face fill.

해석:
- 우리가 겪는 "표면이 옆 mesh/point cloud와 섞이는 문제"에는 아주 직접적이다.
- articulation은 못 하지만, **USDNet 예측 mask를 mesh face 단위로 정리하는 post-refinement**에 좋다.
- REACT3D mesh stage나 Articulate3D object mesh가 있을 때 특히 유용.

우선순위:
- USDNet baseline 결과가 나온 뒤, 예측 mask를 GeoSAM2로 refine해서 mask IoU/visual quality/articulation metric이 올라가는지 보는 것이 좋다.

### 5.5 FIND3D — open-vocabulary part semantic prior

FIND3D는 text query 기반 open-world 3D part segmentation.

가능한 query:

```text
door
drawer
drawer front
cabinet door
handle
hinge
lid
sliding panel
```

해석:
- articulation은 못 한다.
- 하지만 USDNet/GeoSAM2/PartField가 class-agnostic 또는 weak semantic일 때, "이 cluster가 openable일 가능성"을 주는 semantic prior로 좋다.
- 특히 handle/hinge 쪽은 S2O의 hinge heuristic과 결합 가능하다.

### 5.6 CAPNet / ScrewSplat / Articulate Anything / Articulate AnyMesh / PhysX-Anything / PanoGS

요약:

```text
CAPNet:
  single RGB-D에서 articulated part pose/size 추정. object-centric. head idea 참고용.

ScrewSplat:
  3D Gaussian + screw axis optimization. articulated object recognition/kinematic structure에 흥미롭지만 무겁고 scene mismatch 큼.

Articulate Anything:
  VLM actor-critic 기반 articulation generation. pseudo-label/data generation 쪽 후보.

Articulate AnyMesh:
  static mesh -> articulated counterpart. PartSLIP2/GroundingDINO/LangSAM/DINOX/Genesis 등을 사용. synthetic/open-vocab data 후보.

PhysX-Anything:
  single image -> simulation-ready physical 3D assets. PhysX-Mobility dataset 및 URDF/XML generation 쪽 참고.

PanoGS:
  3DGS 기반 open-vocab panoptic segmentation. scene segmentation concept는 좋지만 articulation과 직접 연결되지는 않음.
```

당장 우선순위는 낮다. 하지만 data augmentation, pseudo-label, articulation teacher, future replacement idea로 보관 가치가 있다.

## 6. USDNet 코드 분석에서 확인한 연결 지점

중요 파일:

```text
/home/gpuadmin/capstone/test/p1/datasets/semseg.py
/home/gpuadmin/capstone/test/p1/models/mask3d.py
/home/gpuadmin/capstone/test/p1/trainer/trainer.py
```

확인한 내용:

1. `datasets/semseg.py`
   - 기본 feature는 color.
   - option에 따라 normals와 raw coordinates가 붙는다.
   - `add_raw_coordinates`가 켜져 있으면 coordinates는 model forward에 별도로 들어간다.

2. `trainer/trainer.py`
   - raw coordinates는 `data.features[:, -3:]`에서 분리해서 model로 넘긴다.

3. `models/mask3d.py`
   - Mask3D-style mask/class head에 USDNet articulation head가 붙어 있다.
   - `predict_articulation_mode`에 따라 origin/axis head 동작이 다르다.
   - query seed는 현재 decomposed coordinates에서 FPS로 뽑는 구조.
   - mask logits는 `mask_features @ mask_embed.T` 방식.
   - articulation mode 2는 pointwise origin/axis + query residual을 섞는 구조.
   - mode 3/4는 PCA/heuristic 성격이 섞여 있다.

가장 자연스러운 개조 지점:

```text
1. Post-refinement
   USDNet output mask -> GeoSAM2/PartField/S2O-style refinement
   장점: checkpoint 호환, retraining 불필요.

2. Mask-guided query injection
   FPS query에 SAM/GeoSAM2/FIND3D/PartField proposal center를 추가.
   장점: 구조 변경은 작고, "openable 표면을 못 보고 지나가는 문제"에 직접적.

3. Auxiliary proposal/pseudo-label loss
   GeoSAM2/Any3DIS/PartField proposal을 pseudo mask로 사용.
   장점: USDNet 자체가 clean surface prior를 배우게 할 수 있음.

4. Feature fusion
   2D/SAM/FIND3D/PartField feature를 input channel 또는 decoder feature로 추가.
   단점: checkpoint compatibility가 깨지고 retraining 부담 큼.
```

현재 추천 순서:

```text
post-refinement -> mask-guided query injection -> auxiliary loss -> feature fusion
```

## 7. 이번 세션의 핵심 판단

### 7.1 USDNet을 base로 가는 것이 맞다

이유:
- 목표가 scene-level openable part mask + articulation이기 때문이다.
- S2O/GeoSAM2/PartField/Any3DIS/FIND3D는 각각 강한 조각은 있지만, USDNet처럼 scene point cloud에서 movable mask와 articulation을 한 번에 내는 구조는 아니다.
- 따라서 지금은 USDNet을 대체하기보다 USDNet을 중심으로 보강하는 것이 가장 현실적이다.

### 7.2 REACT3D/GroundedSAM/SAM2를 완전히 버리면 안 된다

정리:
- primary model은 USDNet으로 옮겨갈 수 있다.
- 하지만 GroundedSAM/SAM2/Any3DIS/GeoSAM2는 여전히 강한 2D/mesh prior다.
- 특히 surface가 지저분하게 잘리는 문제는 2D multi-view/mesh face label refinement가 3D sparse model보다 나을 수 있다.

따라서 권장 구조:

```text
USDNet:
  primary scene-level movable/articulation predictor

GroundedSAM/SAM2/Any3DIS/GeoSAM2:
  proposal, mask refinement, failure fallback, pseudo-label

S2O:
  openable object-level heuristic, motion prior, teacher/fallback

PartField/FIND3D:
  partness + open-vocab semantic prior
```

### 7.3 `mov_trainval.ckpt`는 조심해서 써야 한다

사용자가 확인:
- `mov_trainval.ckpt`는 Articulate3D val도 학습한 checkpoint가 맞다.

따라서:
- fair evaluation claim에는 쓰면 안 된다.
- 하지만 practical transfer, teacher, upper-bound, architecture sanity check에는 매우 유용하다.
- clean baseline은 반드시 `Mask3D scannet200_benchmark.ckpt` init run으로 본다.

이 devlog를 만든 뒤, "USDNet을 꼭 원형 그대로 쓸 필요는 없고 encoder/decoder/head를 바꾸거나 추가해도 된다"는 전제에서 최신 repo와 로컬 코드를 더 봤다. 결론은 **USDNet은 버릴 대상이라기보다 task scaffold로 유지하는 것이 좋고, 그 안의 query/decoder/head/loss/matcher를 바꾸는 방향이 가장 현실적**이라는 쪽이다.

### 11.1 USDNet 내부 구조에서 확인한 병목

확인한 핵심 파일:

```text
/home/gpuadmin/capstone/test/p1/models/mask3d.py
/home/gpuadmin/capstone/test/p1/models/matcher.py
/home/gpuadmin/capstone/test/p1/models/criterion.py
/home/gpuadmin/capstone/test/p1/trainer/trainer.py
/home/gpuadmin/capstone/test/p1/conf/model/mask3d_articulation.yaml
/home/gpuadmin/capstone/test/p1/conf/loss/set_criterion_articulation.yaml
```

구조 요약:

```text
input:
  3D sparse point cloud features
  현재는 raw xyz/color 기반. 2D mask나 SAM confidence는 본체 입력에 직접 들어가지 않음.

backbone:
  Res16UNet34C / MinkowskiEngine sparse UNet

query:
  non_parametric_queries=True
  FPS로 scene point에서 100개 query coordinate를 뽑음
  use_np_features=False라 query content는 사실상 zero에서 시작하고 positional encoding만 강하게 들어감

decoder:
  Mask3D style multi-level cross-attention/self-attention/FFN

mask output:
  query embedding과 point mask feature의 dot product

articulation:
  predict_articulation_mode=2
  predicted mask를 sigmoid > 0.5로 hard threshold
  그 mask 안의 pointwise origin/axis를 평균내서 query-level origin/axis로 만듦
```

가장 중요한 병목:

1. `matcher.py`의 Hungarian matching이 articulation을 보지 않는다.
   - config에는 `matcher_cost_origin`, `matcher_cost_axis`가 있지만 실제 final cost는 class + mask BCE + dice만 사용한다.
   - 그래서 mask matching이 흔들리면 origin/axis loss도 잘못된 query에 붙을 수 있다.

2. articulation head가 predicted hard mask에 너무 의존한다.
   - `outputs_mask.sigmoid() > 0.5`로 feature mask를 만들고 origin/axis를 평균낸다.
   - openable mask가 지저분하면 articulation은 바로 같이 무너진다.

3. 현재 USDNet은 2D mask를 3D로 올리는 구조가 아니다.
   - GroundedSAM/SAM2/Any3DIS/GeoSAM2 같은 2D/mesh proposal을 그대로 쓰지 않는다.
   - 따라서 "2D->3D quality map" 아이디어는 현재 구조 안에 이미 있는 것이 아니라, query prior/pseudo-label/refinement로 새로 붙일 수 있는 아이디어다.

4. 이번 100epoch 실험은 이미 `loss_regular_arti_loss=False`였다.
   - 즉 단순 L1 articulation loss가 아니라, axis cosine + origin-to-axis-line distance 계열의 geometry-aware loss로 돌았다.
   - 그런데도 MAO가 낮으므로 다음 병목은 loss 형태 하나보다 mask quality, matching, query/head 구조 쪽일 가능성이 크다.

### 13.3 다음 구조 변경 1순위

가장 먼저 해볼 구조 변경:

```text
USDNet 유지
  + articulation-aware matching
  + movable/openable center 또는 bbox center head
  + Relation3D-style center cost / feature similarity loss
```

구체적 이유:

```text
현재 matcher는 class/mask/dice만 보고 query-GT를 매칭한다.
하지만 articulation head는 그 matching 결과에 따라 supervision을 받는다.
따라서 origin/axis 또는 center/bbox를 matching cost에 넣는 것이 가장 직접적인 개선이다.
```

가능한 작은 실험:

```text
A. matcher cost에 origin/axis cost 추가
B. pred_mov_centers=True 활성화 후 loss/matcher에 center cost 연결
C. Relation3D처럼 bbox/center head 추가
D. same-instance feature similarity loss 추가
```

